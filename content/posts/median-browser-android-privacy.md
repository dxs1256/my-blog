手机浏览器这两年越做越重。随便一个主流浏览器，安装包动辄一两百 MB，启动慢、后台常驻，广告和分析 SDK 塞了一堆，密码存在云端还得绑定账号。我想要的其实很简单：开网页快、别收集我的数据、密码别上传——结果主流产品没一个能同时满足。

最近在 GitHub 上翻到一个叫 **Median** 的项目（⭐144），一句话介绍就很对我胃口：「安装包仅 200KB 的极致轻量化浏览器」。把源码结构和设计文档过了一遍之后，我觉得它把「本地优先」这件事做到了相当彻底的程度。

项目地址：https://github.com/bi-box/Median

## 🎯 200KB 是怎么做到的

Median 不打包自己的 Chromium 内核，而是直接复用 Android 系统自带的 System WebView 渲染网页，界面和功能模块用原生 Java 写。所以安装包只有 215KB 级别，渲染兼容性和性能跟着系统 WebView 走，系统更新它也跟着更新，不用等厂商单独发版本。

体积小只是表象，真正的关键在这里：**整个浏览器没有任何广告、分析、崩溃上报 SDK，也没有开发者运营的账号或同步服务器**。书签、历史、密码、脚本、下载记录默认全部存在设备本地。

## 🛡️ 广告拦截：ABP/hosts 规则，纯本地过滤

内置 AdBlockEngine，兼容 ABP / hosts 规则，支持订阅在线过滤列表、元素隐藏、清理跟踪参数，还能逐站点开关。过滤完全在本地 WebView 请求回调里完成，不走云端代理——这跟不少号称"广告拦截"、实际把流量转到自家服务器的产品有本质区别。

## 🔐 密码库：Keystore + AES-GCM，全程不出设备

密码存在 PasswordVault 里，密钥由 Android Keystore 生成，AES-GCM 加密；HTTPS 自动填充默认开启，登录后自动提示保存，支持多账号、多步登录、Shadow DOM 和同源 iframe。导出的便携备份还要用户自定义密码二次加密。换句话说：密码从生成、存储到备份，全程不碰云端。

## 🧩 用户脚本：类 Tampermonkey，原生注入

支持类 Tampermonkey 的用户脚本引擎，在 document-start 阶段原生桥接注入，带 GM 兼容层（正则匹配、相对 URL 解析、UTF-8 资源回退），并对脚本权限和 @connect 目标做最小化校验。平时在桌面端用油猴玩的那些网页增强、去广告、显示增强脚本，在手机上也能跑起来。

## 📴 离线阅读 + 下载中心

- 本地 MHTML 归档，离线页面字节不出设备，配合阅读模式、TTS 朗读、网页翻译、页内查找
- 下载中心支持分段下载、暂停/恢复、断点续传，前台服务保活，大文件不中断

## 🕵️ 一个很诚实的细节：隐私窗口

Median 的隐私窗口和普通标签完全隔离，退出即清除。但 README 里明确写了一句：**「无法可靠隔离时，不会伪装成『无痕模式』欺骗用户」**。相比某些产品明明隔不干净还硬标"无痕"，这种诚实反而更让人放心。

## ⚠️ 两个必须知道的点

1. **它不是开源软件**。源码公开可读，但采用「保留所有权利」的源码可见许可，不是 MIT / Apache / GPL。想二次分发、商用，必须先拿到版权方书面授权——别看到 GitHub 仓库就当开源用了。
2. **WebView 的取舍**。依赖系统 WebView 换来 200KB 的体积和零内核维护成本，代价是没法像 Chrome / Kiwi 那样深度定制内核。对绝大多数日常浏览完全够用，但重度折腾党可能会觉得不够。

## 🛠 怎么装上

项目提供完整编译指南：Android Studio + JDK 17，`./gradlew assembleDebug` 直接出包；不想自己编译的，可以加入它的 Telegram 社区（README 里有入口）拿测试包。因为是源码可见许可，暂时没有上 Play 商店的公开渠道，装起来比普通应用多一步。

## 💡 我的判断

我还没在主力机上长期用它（需要自己编译或从 Telegram 渠道装），但从源码结构和设计文档看，它把「数据不出设备」做到了主流浏览器做不到的程度：零遥测、零云端、密码本地加密、过滤本地执行。适合在意隐私、不想被浏览器收集数据、又嫌主流浏览器臃肿的人，也适合喜欢在手机上跑用户脚本的进阶用户。

反过来，如果你离不开 Chrome 的跨设备同步、密码云端自动填充和扩展生态，那它暂时不适合你——本地优先的代价就是没有云同步。我的看法是：把它当「备用隐私浏览器」装一个放着，处理敏感页面时切过去，比指望一个浏览器兼顾所有场景实在得多。
