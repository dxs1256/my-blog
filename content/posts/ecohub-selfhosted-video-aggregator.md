想搞一个自己的影视库，片源却散在网盘、各类接口里，Tvbox 的订阅地址配一次乱一次，后台还看不到采集进度——这种折腾很多人应该都熟。

最近发现了一个叫 **EcoHub** 的开源项目（⭐171），它把"采集 → 整理 → 发布 → 观影"这条链做成一个带管理后台的 Web 服务。前端能直接在浏览器里流畅看，后端接上你自己配置的采集接口，再给 Tvbox 或它的原生 App 出订阅地址。

项目地址：https://github.com/fe-spark/EcoHub

## 🎯 先搞清楚：它管"聚合"，不是"片源"

最关键的一点先说在前面：**EcoHub 不提供、不存储任何影视文件**。片源全部来自你自己配置的采集接口，系统只负责把这些来源采集进来、整理成库、展示出来。官方定位是"帮助开发者和影视爱好者快速搭建属于自己的私人影视库"，仅供学习与技术交流。

它不是破解器，也不是下载器，本质是一套自托管的媒体管理与聚合后台——思路和你自己搭 Jellyfin / Emby 类似，只不过多了一套采集发布机制，对接 Tvbox 生态更顺。

![EcoHub 项目架构说明图](https://i.ibb.co/fzRBC6P8/28aa2cbfc8b9.jpg)

客户端是独立 App 仓库，以子模块形式接进项目：EcoHub for OHOS（鸿蒙客户端）和 EcoHub for Android（安卓客户端，适配开发中）。

## ✅ 能做什么

核心是一套全栈多源采集与管理系统：

- **Web 观影**：前台直接在浏览器看，官方说法是"极致流畅"
- **自动化采集**：管理后台的采集中心做全量采集并发布，发布后前台才出片
- **多源聚合**：采集接口自行配置，多源归到一个库统一检索
- **数据分析看板**：内置访问与采集分析
- **一键在线升级**：后台直接升，不用手动拉容器
- **客户端生态**：给 Tvbox / 影视仓出订阅地址，也能给原生 App 出接入地址

技术层面值得一提：v2.6.x 这一轮做了不少生产可靠性加固——读模型并发用 SingleFlight 防击穿加 Redis 双检、重构查询架构消 OOM、孤儿播放列表清理做削峰、采集失败记录落库并定时重试。这些不是给普通用户看的卖点，但对真要长期跑的人来说，意味着不会动不动崩。

![EcoHub 前台观影界面](https://i.ibb.co/MxCR2Rz9/ab2d097371cd.png)

## 🚀 怎么部署

部署要求不高：Docker 20+、Compose 2+，建议不低于 2 核 2GB。

一键安装脚本跑起来后，编辑 `.env`：用 `openssl rand -hex 32` 的输出填 `JWT_SECRET`，改掉 MySQL / Redis 密码，然后启动。

装完默认这些地址：

| 地址 | 用途 |
|------|------|
| `http://<主机>:3000` | 前台 |
| `http://<主机>:3000/manage` | 管理后台 |
| `http://<主机>:3000/api/provide/config` | 客户端（鸿蒙/安卓 App）接入 |
| `http://<主机>:3000/api/provide/vod` | Tvbox / 影视仓订阅 |
| `http://<主机>:18080/api/*` | API 直连（可选） |

默认账号 admin / admin（读写）、guest / guest（只读）。**对外暴露前必须改默认密码，这是红线。**

判断跑没跑通：前台刚装完是空的，正常——进管理后台采集中心做一次全量采集并发布，前台才会出片。前台一直空，先去后台看采集任务有没有跑完。

![EcoHub 管理后台界面](https://i.ibb.co/6cq9bmHK/61bfbb69e5d8.png)

客户端怎么接：想用 Tvbox 或影视仓，把 `http://<主机>:3000/api/provide/vod` 当订阅地址填进去就行；想用原生体验，鸿蒙和安卓 App 接 `http://<主机>:3000/api/provide/config`。

## ⚠️ 合规与安全边界

这个系统值得折腾，但前提是建立在合法合规的基础上：**片源得是你有权使用的资源**，别拿它去搬运、分发侵权内容。项目本身是 PolyForm Noncommercial 1.0.0 协议，非商业用途，做个人学习和自托管可以，拿去做商业服务、二次打包售卖都不在授权范围内。

安全上也别马虎：生产环境走 Nginx / 1Panel 反代加 HTTPS；不想裸端口对公网，就在 compose 里把端口绑到 `127.0.0.1:`（如 `127.0.0.1:3000:3000`），能避开 Docker 默认规则绕过系统防火墙直接暴露的问题；没有播放器直连需求就把 18080 那段映射注释掉。

## 🎯 我的看法

EcoHub 的定位很清晰：不是又一个"看片网站"，而是把 Tvbox 生态里最烦人的"订阅地址管理"做成了一套正经的自托管后台。如果你手上的片源散在好几个采集源里、一直想归到一个能直接看的库里，它值得折腾一次。在线演示（eco.fe-spark.cn，guest/guest 只读）可以先上去体验一下再决定要不要部署。
